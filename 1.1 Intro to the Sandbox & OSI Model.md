# The OSI model layers:

While I haven't used this much to debug anything, it's somewhat important. There are 7 different layers that data is "packaged" into before being sent across the cable.

Layer 1 or the "Physical" layer is just the physical bits and bytes, the 1's and 0's on the cable. And how the data travels across the cable. Does it use light (fiber optic)? Electricity (ethernet?) Or Wireless (Wi-Fi)? 

Layer 2 or the "Data Link" layer are the hardware addresses (not networking yet). Each device has a unique "mac" address that says stuff like which company made it, the unique ID. The switches usually handle this. This layer lives within a SINGLE network or subnetwork. Not the internet yet.

Layer 3 or the "Network" layer. This is the ACTUAL internet, the IP addresses, and connecting to computers outside your network.

Layer 4 or the "Transport" layer. This layer deals with "ports" which are kind of like different applications. printing, website, ssh. (80 is HTTP and 443 is HTTPS for example. You don't need to remember port numbers because they're all over the internet with a simple google search) It breaks giant files into pieces called "segments" and sends them one at a time, and makes sure they were sent safely, nothing was lost in transit. Besides port numbers, it also deals with TCP and UDP, even though there isn't much difference. TCP is slower but more accurate, where UDP is faster but less accurate. UDP is for live streaming, TCP is for files. That's all I know with this.

Layer 5 or the "Session" layer. This makes sure everything stays "separate". Like your game doesn't get mixed up with zoom, doesn't get mixed up with google chrome, doesn't get mixed up with discord. Again, I have never seen any issues or had to debug this one.

Layer 6 or the "Presentation" layer. Again, I have never needed to debug or tweak this once. This only makes sure the application can read the data, and also encryption and security.

Layer 7 or the "Application" layer. Not the web browser, but the protocol the web browser uses. This is what the user interacts with. Usually programming, raw code
